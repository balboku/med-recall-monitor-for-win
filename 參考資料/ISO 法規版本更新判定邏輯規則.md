# ISO 法規版本更新判定邏輯規則

在進行版本比對前，軟體應**優先判定提取到的文件屬於哪一種 ISO 文件類型**，接著再根據其落在 ISO 主頁的 `NOW` 或是 `Previously` 區塊，來決定最終的更新狀態與提示。

---

## 1. 第一步：文件類型字串判定規則 (優先執行)

軟體在獲取 ISO 文件名稱字串（如 `ISO 2859-1:1999/Amd 1:2011` 或 `ISO/TS 16949:2009`）後，應透過字串包含的**前綴**或**後綴**特徵，依序往下比對並歸類文件類型。

> **💡 開發實作建議**：請務必先判定「後綴 (AMD/COR/ADD)」與「前綴 (TS/TR/PAS)」，如果都沒有命中特徵字串，**最後才將其判定為「主標準 (Main)」**，以避免誤判。

| 軟體判定順序 | 文件類型           | 字串特徵條件           | 說明與特徵                                                   |
| :----------: | :----------------- | :--------------------- | :----------------------------------------------------------- |
|    **1**     | **修正案 (AMD)**   | 包含 `/Amd`            | 對主標準實質內容的技術修改（例：`.../Amd 1:2011`）。         |
|    **2**     | **技術勘誤 (COR)** | 包含 `/Cor`            | 對主標準排版或文字錯誤的純技術勘誤（例：`.../Cor 1:2001`）。 |
|    **3**     | **補充件 (ADD)**   | 包含 `/Add`            | 極少見的舊制文件，功能類似 AMD，判定邏輯等同 AMD。           |
|    **4**     | **技術規範 (TS)**  | 開頭包含 `ISO/TS`      | 尚未成為正式標準的過渡性技術規範（例：`ISO/TS 16949:2009`）。生命週期判定原則等同主標準。 |
|    **5**     | **技術報告 (TR)**  | 開頭包含 `ISO/TR`      | 純粹提供資訊或指導方針的文件（例：`ISO/TR 10013`）。生命週期判定原則等同主標準。 |
|    **6**     | **公開規範 (PAS)** | 開頭包含 `ISO/PAS`     | 因應市場緊急需求快速發布的短期規範。生命週期判定原則等同主標準。 |
|    **7**     | **主標準 (Main)**  | **不包含**上述任何字串 | 單純的 `ISO 數字:年份`，代表完整的獨立標準文件。             |

---

## 2. 第二步：生命週期狀態判定總表

判定完文件類型後，依據文件落在 ISO 官網的 `NOW` 或是 `Previously` 區塊，給予對應的系統狀態。

| 網頁落點區塊   | 軟體判定文件類型                   | 系統判定狀態                  | 系統動作與提示方針                                           |
| :------------- | :--------------------------------- | :---------------------------- | :----------------------------------------------------------- |
| **NOW**        | 任何類型 (包含主標準/AMD/COR/TS等) | **🟢 無更新 (Up-to-date)**     | 顯示「文件為最新有效版本」，無需動作。                       |
| **Previously** | 主標準 / TS / TR / PAS             | **🔴 已改版作廢 (Obsolete)**   | 警告「標準已改版」，提示需取得 NOW 區塊的新版主標準。        |
| **Previously** | 修正案 (AMD) / 補充件 (ADD)        | **🟡 已整合作廢 (Integrated)** | 提示「此修正案已作廢，內容已整合至新版主標準」，建議取得 NOW 區塊的新版主標準。 |
| **Previously** | 技術勘誤 (COR)                     | **🟡 已整合作廢 (Integrated)** | 提示「此技術勘誤已作廢，內容已整合至新版主標準」，建議取得 NOW 區塊的新版主標準。 |

---

## 3. 第三步：軟體判定邏輯與執行細節

### 情境一：文件落於 NOW 的區塊
* **判定條件**：`User_Doc IN ISO_NOW_List`
* **系統邏輯**：文件與 ISO 官方目前宣告為「已發布 (Published)」的版本吻合。
* **執行動作**：狀態標記為 `Valid`。

### 情境二：文件落於 Previously 的區塊
當判定條件為 `User_Doc IN ISO_Prev_List` 時，文件已失效，需進一步依據第一步判定的「文件類型」給予指引：

**A. 舊版主標準 (包含 TS / TR / PAS)**
* **執行動作**：狀態標記為 `Obsolete`。
* **使用者提示**：「您持有的舊版文件已作廢，請更新至 {NOW_Version} 版」。

**B. 舊版修正案 (AMD / ADD)**
* **執行動作**：狀態標記為 `Integrated`。
* **使用者提示**：「您持有的舊版修正案已失效，相關技術變更已整合至最新版主標準 {NOW_Version}，請直接取得新版主標準」。

**C. 舊版技術勘誤 (COR)**
* **執行動作**：狀態標記為 `Integrated`。
* **使用者提示**：「您持有的舊版技術勘誤已失效，相關勘誤已於最新版主標準 {NOW_Version} 中修正，請直接取得新版主標準」。

---

## 4. 進階防呆規則 (Edge Case)

在完成上述基礎判定後，建議加入一條額外的檢查機制，確保使用者不漏接最新發布的修正檔：

* **檢查 NOW 區塊是否包含附屬文件**
    * **判定條件**：`User_Doc == NOW_Main_Version` AND `ISO_NOW_List CONTAINS "Amd" OR "Cor"`
    * **系統邏輯**：使用者的主標準是最新的，但官方近期針對此最新版發布了新的獨立修正 (AMD) 或勘誤 (COR) 文件。
    * **執行動作**：狀態標記為 `Valid_With_Updates`。
    * **使用者提示**：「您的主標準為最新版，但官方已發布最新的補充文件 {NOW_AMD_COR_Version}，請確認是否需要一併取得。」
