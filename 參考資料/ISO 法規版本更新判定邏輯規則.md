# ISO 法規版本更新判定邏輯規則 

在進行版本比對前，軟體應優先判定提取到的文件屬於哪一種 ISO 文件類型，接著根據其落在 ISO 官網的搜尋結果（無結果、`NOW` 區塊、或 `Previously` 區塊），並結合內部資料庫的比對結果，來確保**標準家族（主標準＋附屬文件）的完整性**，最終輸出至「狀態欄位」的標準化字串。

---

## 1. 第一步：文件類型字串判定規則 (優先執行)

透過字串包含的前綴或後綴特徵，依序往下比對並歸類文件類型。請務必先判定「後綴」與「前綴」，最後才判定「主標準」。

| 軟體判定順序 | 文件類型           | 字串特徵條件           | 說明與特徵                                           |
| :----------: | :----------------- | :--------------------- | :--------------------------------------------------- |
|    **1**     | **修正案 (AMD)**   | 包含 `/Amd`            | 對主標準實質內容的技術修改（例：`.../Amd 1:2024`）。 |
|    **2**     | **技術勘誤 (COR)** | 包含 `/Cor`            | 對主標準排版或文字錯誤的純技術勘誤。                 |
|    **3**     | **補充件 (ADD)**   | 包含 `/Add`            | 極少見的舊制文件，判定邏輯等同 AMD。                 |
|    **4**     | **技術規範 (TS)**  | 開頭包含 `ISO/TS`      | 尚未成為正式標準的過渡性技術規範。                   |
|    **5**     | **技術報告 (TR)**  | 開頭包含 `ISO/TR`      | 純粹提供資訊或指導方針的文件。                       |
|    **6**     | **公開規範 (PAS)** | 開頭包含 `ISO/PAS`     | 因應市場緊急需求快速發布的短期規範。                 |
|    **7**     | **主標準 (Main)**  | **不包含**上述任何字串 | 單純的 `ISO 數字:年份`，完整的獨立標準文件。         |

## 2. 第二步：生命週期與資料庫狀態判定總表

此表定義了軟體最終應寫入系統「狀態欄位」的標準字串。

| 官網落點區塊   | 軟體判定文件類型 | 內部資料庫與官網檢查                                   | 狀態欄位輸出值            | 系統動作與提示方針                                |
| :------------- | :--------------- | :----------------------------------------------------- | :------------------------ | :------------------------------------------------ |
| **查無網頁**   | 任何類型         | (略過不查)                                             | **查無結果，可能已作廢**  | 提示標準可能已撤銷且無替代版本，需人工確認。      |
| **NOW**        | 任何類型         | 官網無附屬文件，或資料庫**已齊全**收錄主標準與附屬文件 | **無更新**                | 顯示「文件與附屬資料皆為最新且齊全」。            |
| **NOW**        | 任何類型         | 官網有 AMD，且資料庫有主標準，但**缺少 AMD**           | **有更新 (缺少 AMD)**     | 提示需補充最新的 AMD 文件。                       |
| **NOW**        | 任何類型         | 官網有 COR，且資料庫有主標準，但**缺少 COR**           | **有更新 (缺少 COR)**     | 提示需補充最新的 COR 文件。                       |
| **NOW**        | 任何類型         | 官網有主標準，且資料庫有附屬文件，但**缺少主標準**     | **有更新 (缺少主標準)**   | 提示附屬文件無法獨立使用，需補充最新主標準本體。  |
| **Previously** | 主標準 / 特殊    | (進入第三步判斷 NOW 是否有附屬文件)                    | **有更新 (主標準已改版)** | 警告舊版已失效，提示升級至 NOW 區塊的新版主標準。 |
| **Previously** | 修正案(AMD/ADD)  | (略過不查)                                             | **有更新 (舊版已整合)**   | 提示舊版修正案已失效，需取得 NOW 的新版主標準。   |
| **Previously** | 技術勘誤 (COR)   | (略過不查)                                             | **有更新 (舊版已整合)**   | 提示舊版技術勘誤已失效，需取得 NOW 的新版主標準。 |

*(註：表中的「特殊」泛指 TS / TR / PAS 等文件，其升級邏輯等同主標準)*

## 3. 第三步：軟體判定邏輯與執行細節

### 情境一：查無搜尋結果 (完全作廢且無新版)
當軟體在 ISO 官網搜尋該標準編號，**完全沒有回傳任何結果**或查無此頁面時：
* **狀態欄位寫入**：`查無結果，可能已作廢`
* **使用者提示**：「系統無法在 ISO 官網找到此標準的任何現行或歷史紀錄。該標準可能已全面撤銷且無後續替代版本，請由文管人員人工確認後續處理方式。」

### 情境二：文件落於 NOW 的區塊 (雙向家族完整性檢查)
當判定條件為文件落於 `ISO_NOW_List` 時，必須對整個「標準家族」進行完整性交叉比對：

* **步驟 2.1**：系統確認 ISO 官網 NOW 區塊所列出的**「完整有效文件清單」**（包含最新主標準，以及其下方掛載的 AMD/COR）。
* **步驟 2.2**：比對內部資料庫的收錄狀況：
    * **齊全狀況**：資料庫【有】主標準，且官網列出的附屬文件資料庫也【都有】（或官網根本無附屬文件） ➡️ 狀態寫入 `無更新`。
    * **缺附屬文件**：資料庫【有】主標準，但【無】官網列出的附屬文件 ➡️ 判讀類型後，狀態寫入 `有更新 (缺少 AMD)` 或 `有更新 (缺少 COR)`。
        * *提示：「主標準為現行版本，但缺少最新的補充文件 {NOW_Supplement_Version}，請盡速更新。」*
    * **缺主標準 (新規則)**：資料庫【有】附屬文件，但【無】主標準本體 ➡️ 狀態寫入 `有更新 (缺少主標準)`。
        * *提示：「系統發現資料庫已收錄補充文件 {NOW_Supplement_Version}，但缺少對應的最新主標準本體 {NOW_Main_Version}。補充文件無法獨立使用，請盡速補充主標準。」*

### 情境三：文件落於 Previously 的區塊 (持有舊版，需升級)
當判定條件為 `User_Doc IN ISO_Prev_List` 時，文件已失效。依據「文件類型」進行狀態寫入：

**A. 舊版主標準 (包含 TS / TR / PAS) ➡️ 進階檢查**
* **狀態欄位寫入**：`有更新 (主標準已改版)`
* **邏輯分歧 (決定提示內容)**：
    * **若 NOW 區塊【無】附屬文件**：提示「您持有的舊版主標準已改版，請更新至最新主標準 {NOW_Main_Version}」。
    * **若 NOW 區塊【有】附屬文件**：提示「您持有的舊版主標準已改版，請更新至最新主標準 {NOW_Main_Version}。**注意：新版主標準已發布補充文件 {NOW_Supplement_Version}，請一併取得。**」

**B. 舊版修正案 (AMD / ADD)**
* **狀態欄位寫入**：`有更新 (舊版已整合)`
* **使用者提示**：「您持有的舊版修正案已失效，相關技術變更已整合至最新版主標準 {NOW_Main_Version}，請直接取得最新版主標準」。

**C. 舊版技術勘誤 (COR)**
* **狀態欄位寫入**：`有更新 (舊版已整合)`
* **使用者提示**：「您持有的舊版技術勘誤已失效，相關勘誤已於最新版主標準 {NOW_Main_Version} 中修正，請直接取得最新版主標準」。
