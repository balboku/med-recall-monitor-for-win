* * * # ISO 法規版本更新判定邏輯規則
    
        在進行版本比對前，軟體應優先判定提取到的文件屬於哪一種 ISO 文件類型，接著根據其落在 ISO 官網的 `NOW` 或是 `Previously` 區塊，並結合**內部資料庫的比對結果**，來決定最終的更新狀態與提示。
    
        ---
    
        ## 1. 第一步：文件類型字串判定規則 (優先執行)
    
        透過字串包含的**前綴**或**後綴**特徵，依序往下比對並歸類文件類型。請務必先判定「後綴」與「前綴」，最後才判定「主標準」，以避免誤判。
    
        | 軟體判定順序 | 文件類型           | 字串特徵條件           | 說明與特徵                                           |
        | :----------: | :----------------- | :--------------------- | :--------------------------------------------------- |
        |    **1**     | **修正案 (AMD)**   | 包含 `/Amd`            | 對主標準實質內容的技術修改（例：`.../Amd 1:2018`）。 |
        |    **2**     | **技術勘誤 (COR)** | 包含 `/Cor`            | 對主標準排版或文字錯誤的純技術勘誤。                 |
        |    **3**     | **補充件 (ADD)**   | 包含 `/Add`            | 極少見的舊制文件，判定邏輯等同 AMD。                 |
        |    **4**     | **技術規範 (TS)**  | 開頭包含 `ISO/TS`      | 尚未成為正式標準的過渡性技術規範。                   |
        |    **5**     | **技術報告 (TR)**  | 開頭包含 `ISO/TR`      | 純粹提供資訊或指導方針的文件。                       |
        |    **6**     | **公開規範 (PAS)** | 開頭包含 `ISO/PAS`     | 因應市場緊急需求快速發布的短期規範。                 |
        |    **7**     | **主標準 (Main)**  | **不包含**上述任何字串 | 單純的 `ISO 數字:年份`，完整的獨立標準文件。         |
    
        ---
    
        ## 2. 第二步：生命週期與資料庫狀態判定總表
    
        判定完文件類型後，依據 ISO 官網的 `NOW` / `Previously` 狀態，以及內部資料庫是否齊全，給予對應的系統判定與輸出結果。
    
        | 官網落點區塊   | 軟體判定文件類型           | 內部資料庫檢查                                       | 系統判定結果                      | 系統動作與提示方針                                           |
        | :------------- | :------------------------- | :--------------------------------------------------- | :-------------------------------- | :----------------------------------------------------------- |
        | **NOW**        | 主標準 / TS / TR / PAS     | 官網無附屬文件，或資料庫**已**收錄官網列出的 AMD/COR | **🟢 無更新**                      | 顯示「文件與附屬資料皆為最新版本」，無需動作。               |
        | **NOW**        | 主標準 / TS / TR / PAS     | 官網有附屬文件，但資料庫**未**收錄該 AMD/COR         | **🔵 有更新：缺少 {AMD/COR} 版本** | 明確輸出缺少的類型（如「缺少 AMD 版本」），並提示補充該文件。 |
        | **Previously** | 主標準 / TS / TR / PAS     | (略過不查)                                           | **🔴 已改版作廢**                  | 警告「標準已改版」，提示需取得 NOW 區塊的新版主標準。        |
        | **Previously** | 修正案 (AMD) / 補充件(ADD) | (略過不查)                                           | **🟡 已整合作廢**                  | 提示「此修正案已作廢，內容已整合至新版主標準」，建議取得 NOW 的新版主標準。 |
        | **Previously** | 技術勘誤 (COR)             | (略過不查)                                           | **🟡 已整合作廢**                  | 提示「此技術勘誤已作廢，內容已整合至新版主標準」，建議取得 NOW 的新版主標準。 |
    
        ---
    
        ## 3. 第三步：軟體判定邏輯與執行細節
    
        ### 情境一：文件落於 NOW 的區塊 (需執行資料庫交叉比對)
        當判定條件為 `User_Doc IN ISO_NOW_List` 時，代表使用者的主標準是最新的。此時必須觸發**內部資料庫檢查機制**：
    
        * **步驟 1.1**：軟體檢查 ISO 官網的 NOW 區塊下方，是否帶有生效中的附屬文件（例如 `ISO 3601-3:2005/Amd 1:2018`）。
        * **步驟 1.2**：
            * **若官網【沒有】附屬文件**：輸出判定為 `無更新`。
            * **若官網【有】附屬文件**：軟體需搜尋內部資料庫，確認是否已具備該附屬文件的紀錄。
                * **資料庫【有】該附屬文件**：輸出判定為 `無更新`。
                * **資料庫【無】該附屬文件**：
                    * **邏輯**：軟體判讀官網上該附屬文件的字串，辨識其為 AMD 還是 COR。
                    * **輸出判定**：動態顯示 `有更新：缺少 AMD 版本` 或 `有更新：缺少 COR 版本`。
                    * **使用者提示**：「您的主標準 {NOW_Main_Version} 為現行版本，但系統發現缺少最新的補充文件 {NOW_Supplement_Version}，請盡速更新資料庫。」
    
        ### 情境二：文件落於 Previously 的區塊
        當判定條件為 `User_Doc IN ISO_Prev_List` 時，文件已失效，需進一步依據「文件類型」給予指引：
    
        **A. 舊版主標準 (包含 TS / TR / PAS)**
        * **輸出判定**：`已改版作廢`。
        * **使用者提示**：「您持有的舊版文件已作廢，請更新至最新主標準 {NOW_Main_Version}」。
    
        **B. 舊版修正案 (AMD / ADD)**
        * **輸出判定**：`已整合作廢`。
        * **使用者提示**：「您持有的舊版修正案已失效，相關技術變更已整合至最新版主標準 {NOW_Main_Version}，請直接取得新版主標準」。
    
        **C. 舊版技術勘誤 (COR)**
        * **輸出判定**：`已整合作廢`。
        * **使用者提示**：「您持有的舊版技術勘誤已失效，相關勘誤已於最新版主標準 {NOW_Main_Version} 中修正，請直接取得新版主標準」。
